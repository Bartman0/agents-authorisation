Sequence · Agent authorisation demo

Session purpose is chosen at login, enforced at every hop

Four gates stand between the user and the row: the purpose scope chosen at login (agent/identity.py), the scope ceiling Keycloak puts on each per-service client, the per-session policy decision (agent/authz.py, configured by keycloak/init.py), and row level security in postgres/init/02-rls.sql, which stays the hard backstop. The read path through query_transactions is the same shape without the Keycloak and SpiceDB checks: a finance:read token, a SELECT-only role and a READ ONLY transaction.
